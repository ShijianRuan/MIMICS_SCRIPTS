# Mimics 标注效率：功能机会、交互设计与验证路线

日期：2026-10-01。业务源码基线：`36eac0409d89ea1e8bca5c255f9b6c1cf13e1a32`；承接评审文档提交 `8706feb`。本文只提出设计与开发测试建议，没有实现新功能，也没有在真实 Windows/Mimics/GPU 上测得节时比例。

用户明确工具是开放通用的，已有模型生成草稿、从空白开始交互标注、已有标签修订及训练都可能发生。因此，本篇更新第一轮“按全身器官流程排序”的创新建议：先做跨场景高频动作，再按实际使用情况选择领域扩展。此前 F01–F29 缺陷、W01–W10 工作包、T01–T40 测试编号保持不变。本文 E01–E14 是**候选机会，不是已确认缺陷或已承诺排期**；ET01–ET14 是新增功能被选中后的验收建议。

## 1. 先把效率定义对

值得优化的是“得到一份可交付标注所花的人工时间和返工”，不能只比较模型推理秒数。一次完整工作包含：寻找病例/序列、定位结构、选择工具与参数、绘制或修正、等待、检查、保存导出、故障恢复。后台耗时能与人工操作重叠，不能将每个阶段耗时简单相加当作真实总耗时。

四个视角应同时参与取舍：

| 视角 | 真正要改善的事 | 容易产生的反效果 |
|---|---|---|
| 产品 | 第一次能走通；熟练后能连续完成；任一主路径都可独立使用 | 默认要求训练、强制固定器官模板、安装全部模型才允许开始 |
| 标注者 | 少找目标、少切模式、只改有问题的部位、放心保留已有成果 | AI 改坏已完成区域、重复确认同一上下文、切到别例后突然回写 |
| 架构 | 重用图像和会话；任务有身份；计算可取消；失败可续 | 多模型同时占显存、全图反复复制、后台抢占宿主、重复建状态系统 |
| UX/视觉 | 当前目标、修改范围和下一步始终清楚；常用动作够近 | 大而全工具箱、满屏高亮按钮、只有颜色没有语义、进度弹窗抢焦点 |

建议记录三类指标：①每个病例/结构的实际人工分钟、有效操作数、工具/窗口切换数；②等待期间能否继续编辑、主线程停顿、失败恢复时间；③独立复核质量、漏项、误覆盖和导出返工。不能以更少点击为由删除保护病例身份或人工修改的必要校验。

## 4. 功能卡：改什么、为什么、怎么做

<a id="e01"></a>
### E01 当前结构快捷工作台

**真实动作：** 标注者看见一个边缘错误，往往先在很多 Mask 中找目标，再找 AI 菜单，重新选模式和窗位。应把“这是谁、我要改哪里、下一步是什么”放在同一处。

**最小设计：** 一个可收起的小窗口，上方显示病例/序列、当前结构和二维/三维作用域；中间只放当前意图的几个动作：定位结构、前景/背景、画提示、预览/应用；底部显示计算状态。点/框/涂鸦/套索复用已有捕获逻辑。自由标注可以不选任务模板。结构重叠时列出命中的 Mask 名、所属 Image、颜色与状态，不能偷偷挑第一个。

**实现边界：** 不承诺当前 Mimics 允许第三方 dock 或持续读取鼠标。先验证原生选择与事件 API；无法监听时提供“读取当前选择/刷新”。当前 mask_identifier 源码明确记录模态点捕获与切工具的历史风险，应在目标版本验证捕获、Esc、切焦点、退出，而不是简单删除已有保护弹窗。工具未处于提示捕获状态时，标注者仍应能滚动、缩放和使用原生笔刷。外部 Qt 窗口经已有桥接请求宿主操作，不直接在其进程或工作线程调用 Mimics API。

**验收：** 从“看到错误”到“开始修正”的操作数下降；新用户无需知道算法脚本路径；关闭面板不关闭 Mimics、不终止非本面板任务；换项目立即失效旧目标。关联 W08/W09/W10、T33/T35/T38、ET01。

<a id="e02"></a>
### E02 可选标注清单与位置书签

**真实动作：** 多器官项目要记住哪些做完；单器官长序列中途离开后要找回上一层。两者都需要轻量进度，不能都被迫使用病例×器官大表。

**最小设计：** 单结构模式显示“继续上次位置”；多结构模式显示下一未完成项，可展开清单。结构状态至少区分未开始、处理中、待复核、已复核；另外记录存在、明确缺失、视野外、未知。模板仅预填期望结构、命名和常用窗位，允许增删、自由命名。空 Mask 不自动代表真实阴性。

**实现边界：** 复用 CaseRef/TargetRef/MaskSpec，书签保存物理位置、所绑定 Image、可获取的视图/窗位、当前任务。布局 API 可用不代表能读写所有相机和切片状态；只能恢复已验证字段，其余显示位置提示。项目重新载入时重新绑定对象，不能仅以同名 Mask 恢复旧引用。仅滚动经过一层不算已审阅，切换下一项也不隐式完成上一项。

**验收：** 三病例×三结构在中断/重开后能找回；单结构用户无额外建表负担；缺失/视野外/未标不混淆。关联 W03/W04/W10、T31/T33、ET02。

<a id="e03"></a>
### E03 限定区域修正，保留已完成部分

**真实动作：** 肝脏只有靠近膈肌的十几层需要修；一个肿物只在某一角多出一块。用户需要的是“只改这里”，而非接受模型重新决定整个结构。

**最小设计：** 支持当前层、明确层范围、框选 ROI 三种授权范围；可另标保护区。开始前显示“仅修改此范围”，预览新增/删除，明确应用或丢弃。默认是当前结构的新建议，既有人工结果作为基线保留。任意斜切视图的范围必须转换到有明确厚度的物理区域，不能把屏幕矩形当轴向数组 bbox。

**实现要点：** 对二值目标，令 A 为允许修改区减去保护区，M 为申请时基线，P 为模型/工具建议，候选结果为 `(M ∩ 非A) ∪ (P ∩ A)`。模型读取的上下文可大于 A；不能通过过小输入裁剪损害预测后再宣称是原模型效果。部分提示方法本来就只返回变化区域，仍需与授权范围分别验证。范围边界处显示潜在接缝；加减模式、其他 Mask 的互斥/重叠规则显式配置。

**并发和撤销：** 写入前核对目标及内容 revision。若人工已改基线，先保留新草稿并提示重新预览，不自动用上式覆盖新编辑。撤销仅针对本次已应用变化；其后又有人工修改时，不可盲目把整 Mask 恢复旧快照。保护区是应用层约束，不宣称原生笔刷也被锁住。

**验收：** ROI 外体素逐一不变；保护区不变；删除一个体素同时补一个体素也触发冲突；更换项目零写入；取消不会留下空对象。先满足 F19/F20/F21 与 W02/W04，再做 ET03。

<a id="e04"></a>
### E04 检查“这次改了哪里”，结果到达后再选择处理

**真实动作：** AI 做完后用户难以判断改进发生在哪；看完整器官很费时，直接覆盖又不放心。另一种情况是结果完成时用户正在修别的结构。

**最小设计：** 结果收件区显示目标和状态，不抢焦点；进入预览后可在原始/建议之间切换，或显示新增、删除两类变化。提供“上一处变化/下一处变化”。较大结果可按空间连通区域逐个接受/拒绝；复杂多结构结果第一版可只做整份接受/拒绝。

**实现要点：** 在已确认同网格的二值结果上计算 `added = P & ~M`、`removed = M & ~P`。差异在外部算，宿主只呈现轻量临时 Mask/已验证的显示方式；颜色同时配文字图例，不要求跨版本支持透明叠层 shader。原位切换比较时保留源数据和显示状态，不能靠反复覆盖原 Mask 模拟预览。每次局部接受后更新 revision 与剩余差异，重复点击应幂等。清理仅处理本次拥有的预览对象。

**边界：** “没有变化”不等于“没有错误”；预览不等于复核完成。不能把既有任务缓冲提前删除的 F02 带入新收件区。

**验收：** 已知变化全部可定位；用户当前工具不被强制中断；只接受一处时其余差异不写入；接受后原生 Undo/扩展 Undo 的实际范围有明确说明。关联 W02/W04/W06/W10、ET04。

<a id="e05"></a>
### E05 可解释的检查位置导航

**真实动作：** 全身千层影像、细小结构或多器官结果，耗时经常在找错。先让用户知道哪里值得看，比不停添加分割模型更直接。

**最小设计：** 第一版只做三类候选：孤立小连通域、沿物理方向的截面积突变、用户选定的两份分割之间的差异。每项显示原因、结构、位置和“已看/保留/需要修正”；可一键定位。过滤器由任务决定，不用全身器官的体积阈值评价病灶或血管。

**实现要点：** 计算在外部，输出小型位置清单；距离、体积、连续性尽量用 mm/mm³ 表达并记录坐标。截断 FOV、术后、正常分叶/分支都可能被标记，规则只能提示，不能自动清除。没有校准过的概率就显示“规则提示/模型分歧”，不能伪装成错误概率。模型一致时也可能共同出错，保留常规三平面检查和抽样检查。

**验收：** 合成已知缺陷的定位正确；真实样本由独立复核者标记提示是否有用；记录每十个提示的有效数、定位时间、漏检。高误报时允许关闭单条规则，排序改善以实测为准。关联 W03/W09/W10、ET05。

<a id="e06"></a>
### E06 把原生操作组成少量可预览动作

**真实动作：** 骨骼/气腔常重复“阈值→选种子→取连通域”；泄漏常重复“限定区域→去掉小岛/分离连接”；器官结果常需要与另一个 Mask 做布尔操作。

**最小设计：** 首批三个命名明确的组合：①保留指定种子所在部分；②只在当前 ROI 内应用阈值；③预览小连通域并选择移除。参数旁写单位和作用域，一次预览、一次应用。根据结构可推荐动作，但不自动执行。

**实现要点：** 原生 API 已存在且行为满足需求时优先使用。CT 阈值经当前图像 HU/GV 转换，MR 不套 CT HU；不要照抄历史示例中的数值。现有形态学 API 示例按像素设置，各向异性影像上“2 mm”不能直接用平均 spacing 换一个整数冒充各向同性球。必要时外部执行按物理距离定义的运算，并单独验证边界与连接性。血管、多个病灶和成对器官不应默认“只保留最大连通域”；种子也应先确认落在目标前景。

**验收：** 操作前后差异可见，取消完全不变；空种子/重叠对象可解释；仅删除明确选择的分量；异常退出恢复 GUI 刷新状态。关联 W02/W03/W08、ET06。

<a id="e07"></a>
### E07 稀疏层面标注助手

**真实动作：** 没有适用模型时，对边界相对平滑的结构逐层描很慢。已有的多切片编辑/3D 插值可先形成草稿，再补困难层面。

**最小设计：** 标出人工确认层、插值范围、待检查范围；引导用户在首尾、形态转折和分支处补输入。优先复用 Mimics 的 Multiple Slice Edit/3D Interpolate，再把局部困难区交给已有 nnInteractive 或二维工具。ScribblePrompt 的二维结果应清楚标为当前层，不默认为三维传播。

**实现边界：** 不承诺“两三层得到可靠整器官”。原生 GUI 的所有笔迹/插值状态未必能通过 API 读取；若不能可靠获取，第一版由用户显式标记人工层，扩展只管理书签与覆盖。原生工具进入/退出可能改变 Mask 可见性，应验证恢复体验。Materialise [官方 FAQ](https://www.materialise.com/en/academy/healthcare/mimics-innovation-suite)提示相邻编辑层之间的插值限制，实际行为依版本核验，不把不可插值当作扩展崩溃。

**训练边界：** 仅标注层与未标区域明确区分。进入普通监督训练之前必须经过完整复核，或走另行实现并验证的稀疏监督协议；不能把未标区域默认为背景。

**验收：** 输入层保持，未授权范围不变；分叉、断续、极薄、各向异性样本可识别失败并转手工；比较最终合格所需人工时间，而非仅比较画了几层。关联 W03/W07/W10、ET07。

<a id="e08"></a>
### E08 把等待变成可预期、可重叠的准备过程

**真实动作：** 第一笔要等模型启动、图像搬运；后台批量预测/训练占满显存，交互请求排队。用户需要知道等待在哪、能否继续画、何时释放资源。

**最小设计：** 显示准备图像、加载模型、等待设备、推理、结果可用五类阶段；“保持交互模型可用/结束后释放”可选。已选病例队列可以只预取下一例的 CPU 数据，GPU 预热仅在空闲且不驱逐当前交互会话时执行。批量计算逐例失败隔离，不改变前台项目。

**实现要点：** 仓库已有保温、预热和图像 worker 复用，应先测命中率与每阶段耗时，不重复实现。缓存 key 包括病例/图像 revision、几何、预处理和模型身份；手工改变图像后重新准备。给缓存设内存/磁盘预算，区分可删缓存和可恢复任务产物。一个长 GPU 调用通常不能即时抢占；交互优先指后续可调度阶段优先，暂停训练只能发生在已支持的安全 checkpoint，不声称“点击就立即暂停”。不要为了腾显存杀掉无归属进程。

**验收：** 冷/热两组分别计时；后台忙时仍可原生编辑；同图第二次提示未重复不必要全图准备；取消后没有幽灵任务；不能以持续占 GPU 获得局部快感却拖慢下一模型。关联 W05/W06/W09、T13/T35、ET08。

<a id="e09"></a>
### E09 将已有远程推理变成标注者能配置和理解的能力

**真实动作：** 多台 Windows 的 GPU/驱动组合不同；某台机器适合 Mimics 浏览，另一台机器有合适 GPU。用户希望选设备后直接工作。

**最小设计：** 本机/已配置服务器两个选项，连接测试显示服务、模型身份、支持的提示类型、繁忙状态；结果中显示实际执行设备。网络中断保留本地工作和已有草稿，给出重试/重新建立会话；不把客户端有 server_url 等同于整条链路已经通过验收。

**上游事实：** 官方 [nnInteractive SERVER_CLIENT](https://github.com/MIC-DKFZ/nnInteractive/blob/master/SERVER_CLIENT.md)提供远程会话、能力信息及会话失效处理，仓库已接入客户端。当前上游说明 GPU 推理跨会话串行；增加 session 数不等于提高吞吐。HTTP 请求和模型等待应留在外部进程，宿主仅做短读写。

**实现边界：** 固定并测试客户端/服务端组合，不能直接以在线 master 替换当前依赖。远端加载的模型必须与请求一致，不能只相信本地 model_dir；能力不足的模式应给原因。服务端会话失效后，只有本地真实保存了输入、完整提示和身份，且重放行为经验证，才能提供重建；否则保留最后结果并明确重新开始，不声称透明恢复。单用户优先已有内网或隧道方式；凭据通过现有配置/环境注入、不进入诊断日志。发送前说明所用服务器及图像传输，避免用户误以为仍在本机。

**验收：** 认证失败、满员、模型不符、断网、超时、服务重启分别测试；其他会话与本地人工编辑保持；比较上传成本与整例节时，低带宽时不默认推荐远程。关联 W05/W06/W09、ET09。

<a id="e10"></a>
### E10 可选预训练多器官草稿提供者

**真实动作：** 常见 CT/MR 器官需要从零标，而当前用户并没有训练数据。一个开箱可用的草稿模型可能比要求先训练更实用。

**候选：** 首先评估 [TotalSegmentator 官方代码](https://github.com/wasserth/TotalSegmentator)。它提供 CT/MR 对应任务及结构子集选项；[原始 CT 论文](https://arxiv.org/abs/2208.05868)和 [MRI 论文](https://arxiv.org/abs/2405.19492)的目标及数据范围需要分别看待。仓库目前的 TotalSegmentator-like 数据目录识别，不等于已经集成其推理。

**最小设计：** 用户选择当前影像、所需结构和已验证质量档，产出未复核草稿；先支持少量实际高频结构，不首次运行就下载所有模型。与当前 nnU-Net/FlexiCT 结果通过同一收件区/Mask 导入路径交付，不新增另一套回写逻辑。

**实现要点：** 固定包版本、task、权重 hash、类别字典和预处理；CT/MR 路由明确。roi_subset/fast 在相应任务中的支持与精度代价实测，不能把省时档说成同等质量。小器官、病变、术后、FOV 截断单独看结果；空输出不代表器官缺失。将代码许可、具体权重/任务可用条件与离线资源写入模型卡。先对单结构结果完成源空间回写验证，再扩多结构。

**验收：** 与“空白交互”和已有模型路径比较达到同等复核标准的人工时间；没有这个包时其他功能正常；预训练结果不覆盖人工成果。关联 W03/W05/W10、ET10。

<a id="e11"></a>
### E11 同患者多期/随访标注迁移

**真实动作：** 同一患者平扫/增强期或随访影像，需要再次标类似结构；直接复制体素通常对不齐，重画又浪费已有成果。

**最小设计：** 用户显式选择同患者的来源与目标序列，查看配准预览，再传播为目标序列的新草稿。先做覆盖相近、形态变化较小的任务；登记明确的源/目标病例与序列、变换、重采样方式、源标注版本。跨患者复制不在首版范围内。

**原生与外部取舍：** 仓库帮助已含 [Image Registration](../MimicsHelp_MD/pages/Mimics%20Reference%20Guide/Image%20Registration.md)及[应用配准](../MimicsHelp_MD/pages/Mimics%20Reference%20Guide/Applying%20the%20registration.md)，描述基于 landmark 的配准和新项目行为。先确认当前版本原生工具能否满足操作及脚本化需求；否则可评估已有外部 Python 环境中的 SimpleITK，不因此更换整个桥接架构。

**实现要点：** 从刚性开始，确有收益才加仿射/可变形。按[SimpleITK 官方配准说明](https://simpleitk.readthedocs.io/en/master/registrationOverview.html)明确 fixed/moving、物理坐标与变换方向：输出网格采样需要到输入空间的映射，不能凭“把源变到目标”的自然语言决定是否取逆。离散标签采用保持类别的采样并检查细结构退化；强度图与标签分开插值。DICOM/RAS/LPS 与单位沿 SourceGeometry 处理。[SimpleITK 空间定义](https://simpleitk.readthedocs.io/en/master/fundamentalConcepts.html)也说明相同数组尺寸并不代表相同物理空间。

**质量门槛：** 看独立 landmark 偏差、轮廓/融合显示、覆盖范围；变形场额外检查不合理折叠/位移。配准分数改善不能直接证明标注正确；病灶进展、器官切除、大形变病例允许拒绝传播。时间点变化不能被“对齐”掩盖。失败保留来源，目标只产生待复核草稿。

**验收：** 已知平移/旋转 phantom、局部重叠、缺失结构和真实双期影像都测试；记录人工修正耗时是否确实少于重画。关联 W03/W10、ET11。

<a id="e12"></a>
### E12 结构字典与交付预检

**真实动作：** 结果本身画得不错，最后却因左右命名、label ID、缺结构或重叠被下游退回。应在工作过程中保持一致，导出前一次说明差异。

**最小设计：** 可选任务模板绑定结构编码、显示名/别名、左右侧、颜色、导出标签及允许重叠关系；自由结构仍可用。导出前列出本次结构、当前复核状态、目标空间、命名和输出冲突，允许只导出明确选中的内容。整例完成与某结构完成独立。

**实现要点：** 名称只用于显示/匹配候选，不能替代对象身份；同名不同 Image 不合并。肝/血管/病灶等重叠不能悄悄压成互斥 labelmap，提供独立二值输出或显式已确认的冲突规则。复用现有快速导出，增加一个与产物版本绑定的清单即可。DICOM-SEG/RTSTRUCT 等只在真实下游要求时增加适配和独立读回测试，不因上游模型可以输出就宣称仓库支持。

**验收：** 另一工具独立打开，验证物理空间、左右、标签、重叠、体素内容；最终目录没有旧/新任务混杂。关联 W03/W08/W10、T32/T39、ET12。

<a id="e13"></a>
### E13 把人工修正变成可复用的难例资料

**真实动作：** 同一种边缘错误在下一例又出现；人工劳动没有形成可复用信息。已有训练能力可以利用修正，但需要防止未完成标签进入训练。

**最小设计：** 完成复核后提供“加入任务样本”，记录修正前后、具体目标、覆盖状态和可选错误类型；由用户主动选择若干已复核病例发起现有任务适配。难例列表可先仅用于教学/回归，不要求立即训练。

**实现要点：** 保留原模型和候选模型，按患者分组冻结验证；部分 ROI 修正只有相应覆盖，不能冒充整器官完整标签。挑选样本同时考虑实际人工成本、任务/模态覆盖和重复性；分歧高不必然是最值得标。无完整事件记录时，前后差异只代表净修改，不能反推所有操作或真实标注时长。用户主动查看汇总，默认不做后台录屏/持续上传。

**验收：** 新模型在独立样本上达到复核质量所需交互次数/时间下降才推荐；未改善可保留旧模型；合并多个时点不能泄漏到验证组。关联 W04/W07/W10、ET13。

<a id="e14"></a>
### E14 轻量交接包和可恢复会话

**真实动作：** 中断一天后忘了问题在哪，或第二位标注者只收到一个 MCS，不知道哪些器官待看。恢复和解释也是人工成本。

**最小设计：** 显式“留个待办”保存结构、物理位置、问题说明、可选截图；“交接摘要”列出已复核/待处理/未覆盖及对应版本。无需用户账号、分派服务或在线协作平台。恢复时先校验当前项目/对象与记录对应，再定位。

**实现边界：** JSON 书签不能恢复未保存的 Mask 体素；必须分清“导航记录已保存”“MCS 已保存”“当前草稿有可恢复副本”。真正的恢复副本需要显式开关、空间预算、原子发布与内容验证；不默认周期性保存/覆盖当前 MCS，尤其不在原生笔刷或模态工具工作中强制保存。重启后只恢复本任务可证明归属的产物。

**验收：** 第二人可按待办定位且不会在错误 Image 写入；项目已有新版时提示摘要过期；崩溃恢复测试核对实际体素，不仅验证书签仍在。关联 W02/W06/W10、ET14。

## 5. 一个面板如何保持简洁、精美

建议先验证可收起的小窗口；嵌入停靠只在实际 API 支持后做。下面是信息分组示意，不是已实现界面，也不规定固定像素宽度：

```text
病例 014 / 静脉期             肝脏 ▾
当前结构：处理中             范围：当前 ROI

修正方式  [原生工具] [AI 提示]
提示       [前景 +] [背景 −]     [画提示]

本次建议：2 处变化             [查看变化]
                                              ← 只突出当前主动作
准备/计算/等待/结果可用         [详情] [取消本任务]

[结构清单 ▸] [检查位置 ▸] [更多 ▸]
```

“画提示”“查看变化”“应用修改”随状态切换，不能同时摆成三个主按钮。训练和模型管理仍在需要时打开，避免占用日常编辑面板。用户应随时看见作用域；二维单层结果不能只在 tooltip 里说明。

视觉规范沿用现有主题，补一页状态与排版规范即可：字体服从系统/DPI，正文不以极小字号换空间；8/12/16 等少量间距；主色只表达当前主要动作；禁用和忙碌状态可区分；错误文字长期可找；长名称可复制/展开；结构色与任务状态色分工。新增/删除差异使用不同颜色加文字/轮廓，不仅依靠红绿辨认。

键盘第一版只保证 Tab/Shift+Tab、Enter、Esc 和可配置的少数动作。先核对 [Mimics 原生快捷键](../MimicsHelp_MD/pages/Mimics%20Reference%20Guide/General%20Shortcuts.md)，只在本窗口/工具活动且没有输入框冲突时处理自定义键。不要将全局单字母快捷键强加给用户。切换正负提示应在按钮和当前捕获提示中都显示，避免记忆当前模式。

没有必要添加持续发光、转圈动画或实时 3D 表面重建。进度变化采用低频文字/轻量进度；Mask 体素修改后可延迟更新高成本 3D 网格。结果到达不抢焦点。高 DPI、双屏切换、窗口移出屏幕、长中文名称是基本验收，不是末尾再做的“美化”。

## 6. 与 Mimics 的职责划分与最小技术增量

```mermaid
flowchart LR
    U[标注者在 Mimics 浏览与编辑] --> C[短时读取当前上下文]
    C --> J[沿用现有任务与文件桥接]
    J --> X[外部计算：AI / 差异 / 规则 / 配准]
    X --> R[结果待处理]
    R --> V[主线程核对目标与内容版本]
    V --> P[预览并显式应用]
    P --> U
```

Mimics 负责原生视图、鼠标编辑、短时对象读写和其支持的事务；外部负责模型、重计算和文件处理。长计算放到外部并不自动解决 UI 阻塞：导出整图、hash、回写大量 Mask 仍应分阶段测主线程时间。不得为了流畅把宿主 API 随意移到工作线程，也不得在整段推理期间关闭 GUI 更新。

沿用 [CaseRef/TargetRef/JobRef 等契约](development-handoff.md)，只添加功能确需的记录：

| 记录 | 最小字段/语义 | 为什么需要 |
|---|---|---|
| 操作建议 | proposal_id、job/attempt、TargetRef、base_revision、作用域/保护区引用、模型或原生动作、产物引用、状态 | E03/E04 的局部修改可校验、可重复处理而不重复写入 |
| 复核位置 | 结构身份、物理坐标/区域、生成规则及版本、原因、结果 revision、用户处理状态 | E05 的提示能解释、能失效；编辑后旧结论不继续显示为有效 |
| 书签 | case/image 绑定、可验证视图字段、物理位置、当前任务、记录时间 | E02/E14 在当前数据上恢复；不假装备份了体素 |
| 任务模板 | 稳定结构代码、可选左右/别名、标签/重叠规则、推荐动作、schema_version | E02/E06/E12 的共用描述；不建复杂本体或插件注册框架 |

扩展现有状态文件即可；一份文件一个明确写入者。不要为了这份路线图引入数据库、常驻调度服务、通用工作流引擎或要求使用者更换到另一套影像编辑器。

API 可行性采用三级标记：A=在目标版本真实通过；B=本地/官方文档有能力描述，待版本验证；C=设计假设。目前本文宿主集成均未取得 A。窗位/布局/布尔等有 B 依据；连续悬停、任意停靠、读取原生笔迹、完整视图快照、某种快捷键挂接属于待核验 C，不能以假 API 写入开发承诺。没有相关 API 时保留明确的菜单引导/手动操作，不用脆弱的屏幕坐标点击维持核心流程。

## 7. 新功能验收卡

## 8. 建议采用的开发顺序

**先把返工风险降下来。** W01/W02 的源数据和人工修改保护，以及 W03/W04/W06 的目标身份、文件寿命和任务终态，是一切自动化回写的前置条件。只做面板外观不能抵消这些风险。

**第一组：完成一次高频局部修正。** E01 小面板、E03 限定区域、E04 差异预览，辅以 E06 的一个原生动作。先让用户用“看到错误→定位→修改→看变化→接受→继续原生编辑”完成闭环。范围只需一个结构/一个结果，不追求所有模型和批量模式同时支持。

**第二组：减少重复与遗忘。** E02 书签/可选清单、E08 既有缓存与调度可观察化、E12 交付预检。E05 规则导航先在少量真实数据上评估误报，再决定是否默认出现。

**第三组：按场景添加计算能力。** 无可用模型且常见器官多时选 E10；多机 CUDA 环境难维护且有服务器时选 E09；多期/随访重复标注显著时选 E11；空白标注常用时选 E07；修正积累充足后再选 E13。E14 可以从本地待办书签开始，与 E02 共用记录。

下一阶段不建议同时引入更多同类分割模型、通用智能代理、自动训练循环或大型协作系统。针对细血管/气道中心线、交互分支选择、多灶编号、二维超声时间序列等，可以作为后续任务包；先收集该任务的输入和交付标准，再比较原生工具、现有模型与专用方法。不能把自然视频传播直接当作任意 3D 医学空间传播。

## 9. 怎么知道确实提效

先做形成性试用，不把小样本结果写成统计学定论。建议至少覆盖三条主路径，各选普通、困难、失败恢复任务；若资源允许，邀请一位新手与一位熟练标注者交叉试用。相同病例重复标容易产生记忆效应，应轮换方案顺序，并使用难度匹配病例；记录各自熟悉程度。

每个任务记录：起止时间、实际人工投入、等待可重叠部分、提示次数、工具切换数、恢复时间、最终修正区域、独立复核问题和交付是否合格。只记录必要操作事件和用户主动备注，不采集与任务无关的活动。准确性按结构采用适合的重叠/表面或连接性指标，加独立复核；小病灶/细分支不能仅以整例平均 Dice 掩盖漏标。

第一轮判定标准可先定为：相同质量要求下人工时间有改善，严重误写/源文件变化为零，失败不造成不可恢复工作丢失，新用户能理解目标和范围。具体“降低多少百分比”和延迟门槛由基线决定，本文不虚构收益。如果有耗时下降但提示误报、漏标或返工上升，应调整设计而不是只报告推理速度。

需要补充的现场材料：实际 Mimics 版本/产品线及可用模块、代表性 CT/MR 和任务规范、常见数据体积/结构数、真实 GPU/驱动组合、是否已有内网计算机、当前一次标注的操作录像或计时记录。现有信息足够先完成设计；这些材料决定最终 API 方案和优先级，不影响已完成的文档交付。
