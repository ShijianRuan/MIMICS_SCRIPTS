# 2026-10-03：按标注者操作路径组织的开发与测试交接

配套 [复核报告](2026-10-03-revalidation.md)，代码基线 `f02cfad4a7b030ac017e0ba30ce8f6f6911f500e`。这份文件描述要改什么、为何改、如何验收；**不是已经实现的功能清单**。工具面向通用标注，不假定只有全身 CT 器官或只有批量草稿这一种工作方式。

## 先按工作结果组织产品

标注者通常要完成“找到正确图像→得到正确结构→修正→确认→保存交付”，而不是学习每一个算法家族。现有 27 个 Scripting Library 入口可以保留，不必开发大型平台；需要在入口之间增加一致的上下文与结果反馈。

| 使用者与实际情境 | 要完成的结果 | 最容易漏掉的判断 |
|---|---|---|
| 新用户，首次用已有模型 | 一例可编辑、可保存的草稿 | 环境可导入不等于模型可用；冷启动不等于卡死；模型支持范围不等于全身所有结构 |
| 熟练标注者，100 多个器官 Mask | 快速定位需要修正的结构 | AI 草稿/人工修订/已审核的差别；左右、重叠、缺失器官和空 Mask 是否有意 |
| 从零勾画病灶或未知结构 | 少量提示后持续细修 | 2D/3D 范围、正负提示、当前切片、当前目标、撤销的粒度 |
| 多期/随访同患者 | 每期有独立且对齐的标注 | Patient、Study、Series、Image、Mask 是不同身份层；同网格不是同病例 |
| 整理混合格式数据 | 只导入指定图像与标签，来源不被改写 | 多系列、DICOM 帧、标签图/概率图、标签名映射、空间单位、压缩文件 sidecar |
| 小样本训练/比较模型 | 得到可复现且有实际改进的模型 | 未标不等于背景；患者级泄漏、固定独立评估集、训练/验证标签版本 |
| 多任务并行，暂停后继续 | 在 Mimics 中继续工作，稍后安全接收结果 | “关闭窗口”不等于停止；停止一个任务不应停止其他训练；文件完成不等于已应用 |
| 下游开发/测试接手 | 可定位、可复现、可判断是否修好 | 源码提交、环境、数据、真实动作、实际产物和 UI 状态必须对应同一轮 |

建议所有会写 Mask 或工程的动作都显示简短上下文条：**病例/期相 · 活动 Image · 目标结构 · 输入版本 · 预计输出位置/方式**。高级技术详情折叠，普通用户不应先理解 buffer、bridge、JSON、CUDA 或 checkpoint 才能完成日常操作。

## 必须贯通的 10 条整段旅程

单个入口成功不代表旅程成功。每条测试记录动作、预期、实际对象/文件与恢复办法，至少覆盖成功和一次失败分支。

1. **DICOM 收集→导入→原空间导出。** 病例含定位像、增强两期和不等间距切片；显式选择系列；验证 Series/Frame 组成、方向、物理点和输出 affine。不能只比较三维预览外观。Enhanced 多帧如未支持，应在写产物前明确拒绝并提供原生导入路径，不能文件计层后继续。
2. **NIfTI + 标签→修改→导出→读回。** 每结构独立二值、整卷多标签、空结构、概率图分别处理。最终逐 Mask/逐标签比较体素，保留 source grid 及语义映射。文件成功写出只是中间结果。
3. **官方交互→ScribblePrompt 局部精修→原生画笔→再次交互。** 旧 logits 与当前 Mask 版本一致才复用；正负点和撤销不误删用户原生编辑。应能说明本次影响全卷、局部 ROI 还是单片。
4. **多器官预测→100+ Mask 复核→交付。** 区分 AI 草稿、已改未审核、已审核、明确空结构；隐藏临时 overlay 不等于从导出中排除。提供未完成结构清单、下一个待处理结构与与上次结果的差异导航。
5. **A 推理时修 B→A 结果到达。** 不抢项目、不自动切回、不写 B；结果待应用。A 重开后复核 Image/版本；A 被 Save As 或移动后有可理解的绑定流程。
6. **导入错误→部分人工修正→撤销。** 撤销前给明确对象列表；保护后续工作；失败保留可重试回执。把正确对象归属、实际 API 和磁盘事务放在同一条测试里。
7. **人工补标→原任务加两例→再训练→比旧模型。** 患者不跨 train/val，中文 case 映射不遗失，固定评估样本与标签版本可追踪。测试预检的“未标/负例/缺结构”语义，不能把没有 mask 文件直接当背景。
8. **AL 排序→查看高分例→修正→明确完成→下一轮。** 单纯打开/叠加只能成为 opened/in_progress；完成由人工确认。模型 pair 身份和标签目标一致；退化/平坦分歧有说明；高分不强制标注，允许跳过并留原因。
9. **网络/GPU/磁盘故障→停止→修复→重试。** 排队、进行中、失联、停止请求、取消、部分失败、完成各有区别；取消不能使已完成产物消失；重复回调/重复启动不重复写 Mask。
10. **新工作站接收模型→离线使用。** 包内依赖/标签表/权重哈希可检查；完整 FlexiCT 推理不再需要另一个未声明的 backbone；验证冷启动与首个响应，缺驱动/模型损坏时回到可执行指导。

## 开发工作包：尽量小，边界清楚

### A：病例、Image、Mask 的身份契约（F01/F20/F33，关联 F19/F22）

统一记录 `source_id`（DICOM Series/Frame 集合或来源图像内容身份）、`case_id`、`image_guid`、`mask_guid`、网格摘要及内容版本。**名字用于显示，几何用于空间兼容，二者都不能单独证明身份。** 不要求建立数据库：每个 job 的 JSON context/manifest 即可。

回写前展示目标，捕获 launch snapshot；回写时再次核对，变化则保留结果待重新应用。无法证明来源时解释缺什么，提供用户绑定，不默默选择第一个 Image。只支持单 Image 的入口在创建临时产物前拒绝多 Image。

### B：保存、导出和撤销协议（F28/F30/F31/F32）

输出文件名在写入前分配并做跨平台冲突检测；一个 job 的缓冲区与最终文件共用同一映射。后台输出新版本优先；对原工程的修改需要清晰边界。发布后的回执必须指向最终路径，回执能证明对象所有权和当时版本。

撤销先 dry-run 生成删除计划，实际删除用验证过的 Mimics container 接口和宿主事务；错误不能 catch 后当成功；部分结果写入清单，保留重试信息。旧回执缺身份不猜。不要把全部工程 SHA 相同当作“没有其他人工对象/编辑”的充分证据。

### C：任务生命周期（F34/F35，关联 F26/F27）

所有请求携带唯一 job ID；病例子任务有独立 ID；UI 行保存该 ID，不靠行号/秒时间做身份。新增任务、采集结果、后台报告与停止标记核对相同 ID。尽量复用现有队列/锁/BackgroundRefresh，不增消息中间件。

建议内部状态到显示语的最小映射：

| 内部事实 | 面向标注者的状态 | 可以做什么 |
|---|---|---|
| 依赖/来源未满足 | 尚未就绪，说明缺项 | 修复/重选，不提供看似可运行的主按钮 |
| 等锁/GPU | 排队中，注明等待资源 | 取消自己的任务 |
| 读取/准备/推理 | 进行中，具体阶段与更新时间 | 继续使用 Mimics；停止能力及生效点明确 |
| 结果已落盘但目标已变 | 结果已保存，等待应用 | 定位原病例/创建副本/丢弃 |
| 已写 stop，worker 未退出 | 正在停止 | 不重复发起，不显示已取消 |
| 部分病例完成 | 部分完成 / 已取消 | 查看成功与失败清单，重试失败项 |
| Mask 已创建 | 草稿已应用，待复核 | 修正、确认完成；不能自动当训练真值 |
| 人工确认 | 已审核 | 导出/入训练集，记录标签版本 |

### D：训练数据与质量解释（F16/F05 + 产品缺口）

轻量 patient_groups CSV/JSON 导入与预览即可，不需要患者管理系统。已有 fold/内部键通过 manifest 翻译，不用目录名猜患者；独立评估集与用于 checkpoint 选择的验证集分开说明。允许声明可信负例，区分“未标这个器官”“器官不存在”“图像只覆盖部分身体”。UI 默认不得把缺文件视为负例。

模型质量页至少包括目标、模态、训练/验证患者数、评估协议、来源/版本、基线对比与失败例，不必添加复杂统计平台。只有 n=3–4 的受控 Dice 结果应如实显示范围和样本数。要评价提效，则记录人工完成用时、修正次数、接受后返工，不以训练 loss 或推理秒数替代。

### E：宿主响应与 UI 成品（F13/F15/F36/F37）

Mimics API 留在经验证的线程；外部计算不保留 live host 对象。跨模态/点选弹窗能否取消、取消是否释放所有权要验证。缓冲区若一次复制不可避，先测量再显示阶段；大数组读写、哈希、网络目录扫描都不能只是改名“后台”后继续在 GUI 跑。

低成本视觉规范建议：8 像素间距步进、4/8/12/16/24 明确使用场景；同一窗口只保留一个上下文主动作；次级/危险/禁用态统一；正文和提示有清晰层级；正常状态不用醒目告警色。数值带单位和格式（mm³、秒、已完成/总数）；长错误可展开复制；长身份有详情区，不靠所有列都设最小 120 像素解决。

## 真正值得做的提效改进：先小范围验证

这些是设计建议，不能与已确认 bug 混算，也不要求扩成企业系统。

1. **结构工作清单 + 下一个待复核。** 为当前 Image 列目标、草稿/人工/已审核状态；点击联动原生可见性与窗位。对 100+ 器官节省找对象的时间，也服务少量病灶。首版可复用现有 metadata/JSON；先测寻找结构和完成复核的时间。
2. **局部变化复核与安全接受。** AI 只显示新增/删除区域和体积变化；大改动需确认，保留副本/撤销。不同模型输出可比较但不替用户做最终判断。先针对一个结构试用，不做复杂多算法自动路由。
3. **确定性的轻量 QC。** 检查空结构、左右命名冲突、意外小孤岛、边界截断、导出几何与标签映射。规则必须可解释、可忽略并记录原因；不能把真实解剖变异直接自动修掉。
4. **固定场景预设。** “已有多器官模型生成草稿”“空白结构交互标注”“当前切片细修”三个入口说明输入、范围、资源和输出；底层仍使用现有 nnU-Net/nnInteractive/ScribblePrompt。避免新增又一套模型中心。
5. **失败项续跑与结果待应用箱。** 复用现有任务记录，集中列出本工作站任务的下一步；只对失败病例续跑。它的价值来自减少丢结果/重复计算，不需要新的调度服务。

暂缓：开放式自然语言自动改项目、任意模型自动选择、无人工确认的跨期传播、再造完整影像 viewer。优先把已有方法的输入/范围/身份/输出闭环做可靠，再以真实人工用时决定是否引入新模型。
