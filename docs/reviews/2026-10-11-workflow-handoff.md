## 最小设计边界

1. 病例/患者/期相、源文件、Mimics Image、Mask、模型、job 和输出版本各有身份；名称、相同网格、相同文件夹均不是充分绑定证据。
2. 模型推理只生成候选结果；回写在主线程核对目标与人工编辑版本。未知状态默认停在待应用，不抢切项目。
3. 原图、人工工程和已审核结果不可因重试、碰撞、转换或取消被改写。缓存是独立可再生数据，模型/回执/唯一结果不得被当缓存清掉。
4. 成功、部分成功、取消、停止请求、失联和失败须对应真实对象/产物。原子写 JSON 不等于多个写者不会丢更新。
5. 导出有明确标签与空间契约；不存在、未标、部分标和确认空结构不能自动合并为背景。
6. 数据/标签/split/model 版本一起解释评估；模型可运行和对当前任务适用是两个维度。

最小状态与产物流程，Mermaid 源码可直接编辑：

```mermaid
flowchart LR
    A[选择病例与目标] --> B[确认来源/模型/标签]
    B --> C[唯一任务与独立结果]
    C --> D[空间与版本校验]
    D --> E[待应用/变化预览]
    E --> F[人工修正与确认]
    F --> G[原生保存]
    G --> H[交付预检与导出]
    D --> X[冲突或失败:保留产物]
    X --> E
```

## 优先工作包与可实施规格

### WP-A：版本与撤销保护，P0/P1（影像集成 + 运行时 + 测试）

关联 U01/F18/F19/F28/F43。新增共用“结果准备/校验/待应用/发布”契约，覆盖 `.mcs`、NIfTI 与 Mask；独立 job 产物包含 case/image/model/input revision/label mapping/output hash。UI 只显示病例、结构、变化量、输出方式；技术字段折叠。

- 自动计算不写现有人工输出；有旧结果默认新版本，替换单独动作。不要把 repo 文件锁当原生 Mimics 保存锁。
- 导入回执带最终文件、任务、对象归属、创建时内容摘要；撤销先列实际会删对象、已修改对象和会保留文件。
- dirty/query unknown/旧回执不足以证明所有权时，停止自动删除并提供备份/手动动作。任何失败保留逐对象执行记录和可恢复结果。
- 关闭窗口不消费回执；取消确认没有对象/文件副作用。宿主 rollback 能否恢复对象和 metadata 必须实际验证。

交付：共用 helper、跨本地/远程 adapter、兼容旧 receipt 策略、用户提示、A01–A04 数据/日志。不要求数据库、Web 服务或工程全历史系统。

### WP-B：统一来源解析与几何，P1（影像数据集成）

关联 U02/F01。一个 `SourceGeometry` 记录图像网格/世界坐标/来源 UID/有效性/是否重采样，导入、导出、训练准备和回写共同使用。多个系列必须选；缺字段或非规则网格明确拒绝，或者显式、可追溯重采样。把 source_grid 与 Mimics resampled_grid 明确区分，标签使用最近邻，概率才允许相应插值。

交付：规则系列/拒绝路径、几何记录、跨流程物理 phantom A05；支持 Enhanced 另立功能，不以补默认值伪支持。先验证薄层 CT、厚层 MR、倾斜图像的原生导入/空间 API，再决定 adapter。

### WP-C：数据、标签与最终 split，P1（训练管线 + 数据负责人）

关联 U03/F16/F44。共用最终划分，保留 patient group、冻结评估集、非空约束；旧 key 映射损坏在预检就报错。训练页添加“分组 CSV/manifest”与可编辑预览，显示未知组数和“按病例独立假设”，无需暴露复杂算法参数。

预检表至少显示：病例、患者组、图像模态、标签完整性、训练/验证/独立评估分配、拒绝原因。多类重叠 fail/priority 必须显式；priority顺序可预览；负例须人工声明。模型推荐只对同任务/同评估版本比较，训练分数与独立分数区分。

交付：最终 splits 与数据清单、本地/远程一致性、迁移说明、A06–A07；明确修改旧数据/标签会创建新版本，旧成绩保留来源。

### WP-D：病例与结构工作状态，P1/P2（产品 + 标注者 + UI）

关联 U04/F05/F45。先定完成语义，再统一单写入口或 revision+短锁，避免并发丢更新。建议只查看/叠加进入 in_progress，reviewed是明确人工确认；状态旁有“撤回上一步”与跳过原因，结果未保存时显示“未保存修改”。

结构清单复用当前 Mimics对象，快速筛选未处理/当前/变更；不复制全部体积进UI。区分 AI草稿、人工改动、已复核、明确空结构和临时层。只检查明显异常并提示，不自动“纠正”左右器官或手术缺失。导出预检使用同一状态和结构集合。

交付：状态定义、轻量侧车 schema、可达交互、A08–A09/A13。F05 仍是决策项，现行自动 annotated 在本次未改。

### WP-E：任务、回执和资源预算，P1/P2（管线 + UI + 测试）

关联 U05/F13/F30/F42。批次用 batch ID + job ID 台账，列待派发/已派发/部分成功/待应用/失败/取消；重试选失败项，第二窗口不能为同一批次重复派发。取消扫描只阻止未派发项，停止已启动任务是另一动作；关闭只隐藏。

索引只记录本工具创建的回执和输出，不全盘递归扫描；优先当前项目，再显式选一次导入。源图转换、缓存和推理都纳入有界调度。每步记持续时间/资源，不以有外部进程证明全程无卡顿。

交付：批次摘要、取消/重试/恢复路径、回执选择、A10–A12。先在代表工作站测性能预算，避免未经测量的硬指标。

### WP-F：UX 与视觉精修，P2（交互/视觉设计 + 标注者）

这是在功能可靠后做的体验工作，不能用测试构造通过替代。使用当前主题，不另创一套系统。
