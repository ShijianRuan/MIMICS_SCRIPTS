基线：`36eac04`；日期：2026-09-30。以下是待实现/待执行的期望行为，不表示当前版本通过。已执行的受控复现和既有测试结果在文末单独列出。问题解释见两轮报告，开发方案见[交接说明](development-handoff.md)，F/T/W 关联见[backlog.json](backlog.json)。

2026-10-01 补充的[标注效率设计](2026-10-01-annotation-efficiency-roadmap.md)另列 ET01–ET14 候选功能验收，复用本计划的 DS 数据与 L1–L4 分层；均为 not_run，不并入既有 T01–T40 的执行统计。

**测试范围与分层**

- L1：纯 Python/文件/合成影像行为测试；检查真实输出内容、输入 hash 和状态，不仅 mock 调用次数或源码字符串。
- L2：真实 Qt 控件测试；构造空/非空数据、选择、点击、刷新和键盘路径，检查 enable/visible/selection/error，不把“窗口能构造”当完成。
- L3：实际 Windows + 指定 Mimics 版本 + Scripting；检查真实 API、项目切换、Mask 内容、Undo、UI响应、取消和保存。fake_mimics 不能代替这一层。
- L4：有权重和实际 GPU 的推理/短训练/跨机迁移，及可选真实 SSH/容器服务器。没有这些环境时标 blocked 或 not_run，不补造通过证据。

每份结果记录：test_id、业务提交SHA、Windows/Mimics/Python版本、环境组合ID、fixture版本、模型/权重hash、执行步骤、expected/observed、pass/fail/blocked/not_run、日志/截图/输出hash与操作者。只用日志“completed”不能判定内容正确。每个文件故障用例都比对输入与既有人工输出在前后的 hash/对象身份。

**建议执行顺序与完成判据**

1. 修复前保留最小红例：T18/T22（P0）、T20/T21/T28（错误对象/旧结果覆盖），并确认执行完全隔离。修复后先过这些，再广泛跑其它套件。
2. 数据层：T01/T16/T22–T25/T29，采用真实文件和独立真值；部署层：T06–T08/T12。L1绿色后才进入高成本模型推理。
3. Mimics与Qt层：T02–T05/T09–T11/T14/T15/T17–T21/T26–T28；至少有一个真实目标版本，记录native API返回与Undo行为。
4. 联合验收：T30–T40。远程不是本地使用的前置条件；若发布支持远程，则必须完成T36。
5. 回归取与改动相关的现有套件。没有新增失败或范围变化，不反复跑同一组构造测试充数。每项F关闭必须有对应T证据；P0或错病例写入未过，不签整体可用。
