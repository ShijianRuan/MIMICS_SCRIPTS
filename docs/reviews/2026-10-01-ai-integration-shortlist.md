# 哪些 AI 集成真的值得做：收敛后的选型意见

日期：2026-10-01。承接[效率设计候选池](2026-10-01-annotation-efficiency-roadmap.md)，以本仓库已有 nnInteractive、ScribblePrompt、nnU-Net、FlexiCT、训练/远程任务和 Mimics 桥接为前提。本文是选型与交接记录，不是安装或实现结果；未下载权重、运行候选模型或测得标注节时率。业务基线仍为 `36eac04`。

**建议现在只给一个全新的通用 AI 提供者最高接入优先级：TotalSegmentator。** 同时将其草稿接到已有 nnInteractive 的受保护修正流程。其余模型按“补一个明确缺口”分别试验，不默认全部加入菜单。优先级是本次的产品/工程判断，不是论文精度排名，也不是已批准的开发排期。

## 1. “成熟”与“值得集成”分开判断

成熟度看六件可核验的事：公开可取得的代码和权重、具体输入输出契约、可复现推理入口、维护/分发路径、适用任务与失败边界、目标环境部署证据。论文影响力、GitHub stars、支持类别数不能替代这些条件。

集成价值再看增量：相对**现有仓库能力**能减少哪些人工动作；是否覆盖常用任务；是否增加一套难以维护的环境、界面或数据系统。一个成熟框架也可能不值得引入；一个强模型也可能因为与现有能力重复而优先级较低。

本文只判断公开组件层面的可接入程度。所有候选在本仓库的 Windows/Mimics 集成状态均为未验证；不同 CUDA/驱动/GPU 的可用性不能从 README 宣称或单台服务器表现推断。

| 工具/能力 | 相对当前仓库的增量 | 可接入程度判断 | 决定 |
|---|---|---|---|
| TotalSegmentator | 常见结构无需本地训练即可先出草稿 | 包、推理接口、权重和任务文档较完整；本地效果未测 | **首选新增**，先少量任务 |
| 已有 nnInteractive + 外部草稿 | 把自动结果直接转为可持续修正的目标 | 已有适配基础；须核验初始标签能力及安全回写 | **优先做组合流程**，不是新增模型 |
| 经验证的专科模型包 | 补齐用户反复标注而通用模型欠缺的结构 | 每个包单独判断；nnU-Net 成熟不等于任意 checkpoint 可用 | **按实际任务精选**，先复用现有推理后端 |
| MedSAM2 / Efficient MedSAM2 | 有关键层/框/RECIST 信息的病灶跨层传播；特定视频任务 | 有代码、权重入口、示例与研究；仍需任务适配 | **有病灶传播需求才试验** |
| NV-Segment-CT / NV-Segment-CTMR | 另一种类别驱动分割或更广任务覆盖 | 有模型卡及推理发布路径；版本、环境和权重条件需区分 | **第二提供者候选，先对照** |
| HD-BET / SynthSeg | 脑 MRI 的脑提取/脑结构预标注 | 较成熟的专用工具；适用任务窄，Windows路径另验 | **只有脑影像高频时接入** |
| BiomedParse v2 | 文本指定目标的分割 | 有3D权重和推理；数据适配、词义与跨域效果需验证 | **研究开关，不进首批默认菜单** |
| MONAI Label / DeepEdit / DeepGrow | 完整标注服务、学习及查看器生态 | 框架成熟；与现有职责高度重叠 | **不整体引入**；团队已部署时例外 |
| 额外的通用 SAM/MedSAM、聊天控制、无人监督质检/训练 | 增量尚未明确或失败成本高 | 各自可用不代表本项目收益成立 | **暂缓** |

## 2. 首选新增：TotalSegmentator，定位为草稿提供者

**它补的缺口：** 当前工具具备多种交互和训练能力，但用户未必已有适合任务的模型或训练数据。可直接使用的常见结构模型，能让一部分工作从描绘转成检查修正。官方项目有 CT/MR 对应任务、CLI/Python 接口与结构子集选项；不同任务和速度档需分别评价。[官方仓库](https://github.com/wasserth/TotalSegmentator)，[Python 接口](https://github.com/wasserth/TotalSegmentator/blob/137311b50e2361fe38f45447808f9d11db259056/totalsegmentator/python_api.py)。

**值得集成的功能形态：** 在 Mimics 选择“生成结构草稿”，勾选结构，选择本机或已配置设备；完成后只导入所选、未复核的草稿。用户继续用原生笔刷或已有 nnInteractive 修正。不要默认生成全部结构，也不要让标注者学习另一套影像查看器。

**最小开发范围：** 一个固定版本提供者、经验证的 CT 任务及单独验证的 MR 任务、明确类别映射、离线模型准备、当前影像/所选病例运行、取消/失败状态、统一结果收件区。`task`、权重 hash、标签字典与模式一起登记，选择专用任务前核对对应权重使用条件。旧目录被识别为 TotalSegmentator-like 不是推理已集成。

**需要做对的地方：** 接收仓库已经选定系列和几何的输入；CLI 中的自动模态猜测不能取代本仓库输入契约；输出回到原图物理空间并复核左右。ROI 子集及快速模式在实际目标上测质量和耗时，不默认与标准模式等价。只将必要结果变成 Mimics Mask，减少上百对象导入和显示开销。

**停止条件：** 某个结构的“等待+人工检查修正+返工”不优于当前交互标注时，关闭该任务/档位的推荐；不能因为其他器官很好就把它一起开放。空结果不能自动标为器官不存在。整个包不可用时保留空白交互路径。

**与现有方法的关系：** 先用现有 nnInteractive 模型核验 `supports_initial_label`、目标 buffer、空间与模型身份，再提供“继续修正这份草稿”。初始标签能力不能从方法名称或不同 checkpoint 的行为类推。[官方 API 能力说明](https://github.com/MIC-DKFZ/nnInteractive/blob/master/API_CHANGES_v2.md)。局部范围、变化预览、版本冲突保护沿用 E03/E04，而不是为新提供者单独写一套覆盖逻辑。

## 3. 更划算的扩展方式：精选任务模型包

现有 nnU-Net/FlexiCT 已经承担训练和预测。对一个高频专门结构，接入**来源明确、验证过的任务权重与完整预处理包**，可能比新增整个基础模型家族更划算。nnU-Net 本身是数据集自适应的监督分割框架，并不是一个下载后能分割任意对象的统一预训练模型。[官方说明](https://github.com/MIC-DKFZ/nnUNet)。

用户面对的是“某模态/某结构的推荐模型”，开发者维护的是固定模型包：输入模态/通道及顺序、训练目标定义、标签/左右/重叠语义、plans/dataset信息、所需自定义 trainer、权重、推理配置、许可/来源、适用与不适用样本。只有完整包能在干净环境加载并复现输出，才登记为可用；不能只接受 `.pth` 文件名便宣布导入成功。

第一版不建设开放插件市场，也不承诺任意 MONAI bundle 或任意 nnU-Net 模型一键兼容。选一个实际反复出现的任务，复用已有后端做成一个包；若其精度或修正成本不优于通用草稿，就不维护它。尤其不能漏掉多通道 MRI 的序列缺失、配准和通道顺序要求。

两个任务窄、但定位明确的例子：

- [HD-BET](https://github.com/MIC-DKFZ/HD-BET)：脑 MRI 提取可作为一个专门动作。官方提供 CLI 与 GPU/CPU 路径，输入是三维 MRI，方向要求和四维限制需要按版本处理。它不等于颅骨、脑区或脑肿瘤分割；没有高频脑提取需求就不安装。
- [SynthSeg](https://surfer.nmr.mgh.harvard.edu/fswiki/SynthSeg)：脑 MRI 结构预标注及其 QC/体积输出可作为脑影像任务候选。其环境和输出分辨率/网格处理需要单独适配；其 QC 不能被推广成所有器官的正确性评分。

这两项不改变工具的通用定位，而是按需提供任务入口。没有证据证明它们能降低当前用户最常见任务的耗时，因此不放入默认安装集合。

## 4. 有差异价值但需试验：MedSAM2

**值得试的具体任务：** 在病灶最清楚的一层画框，向上下层传播为三维草稿；已有 RECIST 或关键层标记时复用这些输入。视频任务只有在数据、帧序、输出和 Mimics 浏览流程都明确后再考虑。这比“再加一个框选分割按钮”更有区别。

此处特指 **bowang-lab/MedSAM2** 及其 [2025论文](https://arxiv.org/abs/2504.03600)，不能与名字相近的 Medical-SAM2 等另一项目混用代码、权重和论文结论。官方仓库提供 CT 病灶、视频及 Efficient MedSAM2 示例；论文中的人工节省结果发生在其研究任务和流程中，不能作为本仓库收益承诺。[官方实现](https://github.com/bowang-lab/MedSAM2)。

**源码揭示的接入成本：** 固定版本 `medsam2_infer_3D_CT.py` 在第188行读取 DeepLesion CSV，第220–230行使用窗位、关键层、层范围和框，第256行使用 CUDA bfloat16，第285行取最大连通域。这个入口是特定数据集示例，不能直接包一层按钮就声称支持任意 NIfTI。[固定源码](https://github.com/bowang-lab/MedSAM2/blob/332f30d420f1d1b08e2a79b3ae6a602458808383/medsam2_infer_3D_CT.py#L188)。

**最小试验：** 一个病灶、一个明确关键层、一个用户框、显式起止层；将样例元数据改为来自本仓库的坐标/强度契约；输出为新草稿。保留原始医学强度到模型输入的转换记录，不能使用屏幕截图作为输入。为非 bfloat16 路径建立实际设备验证；不能从 Efficient 版本的 CPU 目标推断任意版本任意病例都能实时运行。多灶任务禁止无说明地只保留最大分量。

**是否留下的判据：** 与当前 nnInteractive 在同类病灶上比较最终复核质量、人工提示次数、跨层漂移和纠错时间。若优势只体现在研究样例，而用户仍要逐层大量修正，就不新增默认入口。ROI 外保护、首尾层/传播方向、病灶消失处、厚层/斜位、多个邻近病灶都必须验收。此候选为有条件试验，不是当前通用交互后端的默认替代。

## 5. 第二自动分割提供者候选：VISTA/NV-Segment 系列

它值得放入小规模候选对照，但必须先拆开看。上游 [版本对照](https://github.com/Project-MONAI/VISTA/blob/d4a8fe0dbf5cb4b76c531fccca8e29c1e6f6ee45/vista3d/README.md#L32)区分了研究实现、优化发布以及不同能力，不宜都叫“VISTA3D”后按同一接口安装。

| 发布 | 可以探索的增量 | 集成中的关键区别 |
|---|---|---|
| [NV-Segment-CT](https://huggingface.co/nvidia/NV-Segment-CT) | CT 类别驱动分割，也可测试单对象点提示；关注现有方法薄弱的结构/病灶 | 交互的多对象组合受接口限制；点坐标与标签索引必须映射；不能假设支持 nnInteractive 的全部提示 |
| [NV-Segment-CTMR](https://huggingface.co/nvidia/NV-Segment-CTMR) | CT/MR 自动预标注的另一候选，按实际类别需求选择 | 是自动分割版本；模型卡列出 Linux 路径和非商业学术研究的权重条件，不与 CT 版共用许可结论 |

**需要谨慎的三处：**

1. 研究 repo 的旧 MONAI 1.3 代码注明不再继续更新；优先沿当前官方发布路径固定实现和权重，不从旧研究入口起步后到处兼容。[上游说明](https://github.com/Project-MONAI/VISTA/blob/d4a8fe0dbf5cb4b76c531fccca8e29c1e6f6ee45/vista3d/README.md#L136)。模型卡和优化包可能对应不同 MONAI 版本，要验证实际组合。
2. CTMR 类别 ID 可能超过255。中间 labelmap 不得强转 uint8；只有拆成单个二值 Mimics Mask 后，0/1 buffer 才可按相应契约用 uint8。重叠类别不能不经说明先 argmax 丢失。
3. 官方列出的服务器测试硬件不是用户工作站最低配置证明。当前没有实测 VRAM/RAM/时延数据，不能写“8GB必跑”“Windows直接兼容”或“类别更多所以更好”。

**留下的判据：** 选出一个 TotalSegmentator/现有模型没有覆盖或修正成本较高的实际任务，用同一组脱敏病例比较。只有补到缺口才增加第二提供者；如果只是在已有常见器官上表现相当，维护另一环境的价值不足。需要第二模型做分歧提示时可只对困难例离线运行，不能默认每例全量双模型，也不能把模型一致当正确。

## 6. 暂不放入默认功能的方案

**BiomedParse v2：保留实验候选。** 文本指定目标有吸引力，但要验证它能否识别用户实际目标，而非仅省掉一个下拉选择。当前 v2 有公开3D权重，README 说明使用逐层及邻近上下文的处理；3D入口读取预处理 NPZ 的 `imgs` 和 `text_prompts`，输出 `segs`，空间信息需适配层保存并恢复。[官方 README](https://github.com/microsoft/BiomedParse/blob/f571d5ccaa4f8c0479bb89e390a7ef0dfc0736f4/README.md)，[3D入口](https://github.com/microsoft/BiomedParse/blob/f571d5ccaa4f8c0479bb89e390a7ef0dfc0736f4/inference.py#L88)。

截至本次查看，v2 已移除 Detectron2 推理依赖；不能继续用旧安装问题否定它。但“说中文任意描述就能分割”没有本次证据。先试固定医学词表、左右侧、目标不存在、相近词和跨域病例；中文先做可见的规范词映射。用左右术语搜索既有结构字典时，普通搜索/别名就够用。仅在确实减少定位或覆盖了新的目标时考虑正式接入。

**MONAI Label：不整体引入。** 官方提供自动/交互标注、学习服务和查看器集成，确实是成熟框架。[官方项目](https://github.com/Project-MONAI/MONAILabel)。但本仓库已经拥有训练、预测、任务状态、远程和 Mimics 前端；再引入会带来服务与数据状态的重复。若团队已有可用 MONAI Label 服务，可评估一个薄客户端；否则应复用合适模型或算法，不把整个标注平台搬进来。

**更多通用 SAM/MedSAM 或 DeepEdit/DeepGrow：暂缓重复入口。** 先要求候选在低显存、特定模态、提示方式或实际修正成本上带来明确优势。一个算法能运行或论文更近，不足以增加安装、模型选择和测试负担。

**AI 自动质检、自动决定完成：不承诺通用能力。** 可先做可解释规则、选定模型分歧和复核导航；没有针对任务验证的质量预测器，不输出“此 Mask 正确概率”或自动完成状态。共同错误、病变/术后正常差异、FOV 截断都可能令自动评分误导。

**LLM 聊天控制 Mimics、AI 自动训练循环：当前优先级低。** 自然语言若只是替代几个明确动作，会额外增加解释和确认负担。可先用任务搜索、别名、少量可见快捷动作。已复核样本积累后，仍由用户显式发起现有训练；避免模型自动更新导致结果不可追溯。

## 7. 从上一轮14项机会中收敛当前范围

当前更值得投入的是一个短闭环，而非同时落地14项：

1. **先补保护：** 源数据、对象身份、人工修改、任务终态与回写保护按 W01–W06 的相关项处理。
2. **一个新 AI：** TotalSegmentator 草稿，先支持明确任务，不做模型超市。
3. **三个必要交互：** 当前结构入口、限定区域修正、变化预览/接受（E01/E03/E04）；把已有 nnInteractive 接进来。
4. **一个交付保障：** 输出空间/类别/所选结构预检（E12），减少做完后返工。

E02 从简单书签做起；E08 先量化已有复用/保温再优化；E05 只在提示有效率足够时默认启用。配准迁移、完整任务清单、难例自动排序、远程管理大面板、视频支持都按频次与实际缺口再选。这个收敛顺序是对候选池的进一步取舍，不否认那些功能在特定场景有价值。

## 8. 开发和测试应如何验证候选

### 8.1 每个提供者只有最小必要契约

在现有 registry/model card、JobRef、ArtifactRef 上扩展所需字段，不新建通用推理框架：提供者/代码版本、权重 hash、任务与模态/通道、支持的提示、模型空间/强度协议、输出类型/标签字典、设备与依赖组合、许可/资源位置。适配器负责外部计算；宿主只负责短读写与预览应用。

`binary`、`labelmap`、`probability` 明确区分；labelmap 支持实际 ID 位宽；概率必须显式阈值；shape 一致不能替代病例和物理空间一致。超出模型能力的提示应禁用并说明，不静默忽略。图像预处理缓存不能与别的模型错误共用。

### 8.2 四道进入默认菜单的门槛

| 门槛 | 所需证据 | 未通过怎么处理 |
|---|---|---|
| G1 数据与集成正确 | DS01/DS04/DS05/DS06 的源空间、身份、标签值、左右、ROI和保护；模型输出与Mimics回读一致 | 不向使用者开放回写；先修适配 |
| G2 目标环境可重复运行 | 固定代码/权重/依赖，在实际 Windows/Mimics及代表性GPU或远端跑通；冷/热启动、显存和峰值内存记录 | 标实验能力/不支持组合，不假全绿；不同时升级全仓库环境 |
| G3 比当前流程真正节时 | 普通、困难和失败恢复任务；当前流程与候选交叉试用；最终独立复核达到相同质量 | 未减少人工负担则不成为默认，不能用推理速度代替 |
| G4 维护与失败恢复可接受 | 缺权重、离线、取消、OOM、错误空间、模型切换、目标已编辑；结果归属清楚、源和人工数据不变 | 保留为受限试验或放弃，不以加确认弹窗掩盖数据风险 |

针对每项候选的最小差异测试：TotalSegmentator 测 CT/MR 任务、子集、空输出和质量档；MedSAM2 测层序/首尾/方向与多灶；NV 测各版本能力、超过255标签、类别/点提示组合和重叠；专科包测缺通道/错协议；BiomedParse 测左右/同义词/不存在目标和 NPZ空间恢复。沿用[测试计划](test-plan.md)的 L1–L4，关联效率方案 ET03/ET04/ET09/ET10，不把尚未执行的项目计为通过。

初次比较先用少量有代表性的脱敏例筛选，再扩大覆盖。记录实际人工投入、总周转、错误、返工、安装维护耗时；同一人反复标同一例存在记忆效应，要交叉顺序或使用难度匹配病例。所有质量优势、消费级GPU性能与节时比例仍是待测项。没有现成标注真值时要安排独立复核，不能用候选模型自己的置信度作唯一裁判。
